Overview

교육을 통과해야 거래가 열린다

모의투자를 교육의 보상이 아니라 교육의 연장선에 두기 위해, 제품 구조와 체결 규칙을 그렇게 설계했습니다.

청소년 금융교육은 대체로 읽고 끝난다. 반대로 실전 투자 앱은 미성년자에게 열려 있지 않고, 열려 있더라도 손실 위험을 그대로 진다. 배움과 실행 사이가 비어 있다.

FinPle은 그 사이를 메운다 — 배운 것을 실제 시장 데이터 위에서 위험 없이 실행해 보게 한다.

교육 트리(Level 0–20)를 통과하면 거래가 열리고, 체결은 실제 KRX 종목 2,770개의 시세로 돈다. 수수료 0.015%, 매도 거래세 0.23%, 슬리피지 허용 0.5%, 주문 가능 시간까지 실제와 같은 규칙을 적용해 ‘장난감 계좌’와 구분했다.

투자 결과가 아니라 투자 습관을 보상한다. 수익률 보상 미션은 은퇴시키고 최대낙폭 관리·분산 보유 미션으로 대체해, 수익률을 좇는 유인을 제품에서 걷어냈다.

Engineering

핵심 구현

모의투자라도 규칙이 실제와 다르면 배움이 왜곡됩니다. 체결·시세·보상·랭킹 네 축을 실제 시장 제약에 맞췄습니다.

01  ORDER

주문 체결 엔진

시장가·지정가 주문을 받아 수수료와 세금을 실제 요율로 차감하고, 표시가와 체결가의 괴리가 허용치를 넘으면 체결을 거절합니다. 주문 가능 시간은 fail-closed가 기본값이라 설정이 비어 있으면 거래가 막히는 쪽으로 떨어집니다.

정합성 검증은 눈이 아니라 계산으로 했습니다 — 운영 계정으로 매수 5건을 체결한 뒤 수수료 372원을 포함한 총자산 9,994,628원이 장부와 일치하는지 검산했습니다.

02  MARKET DATA

4단 폴백 시세 파이프라인

외부 시세는 언제든 끊깁니다. 그래서 단계마다 다음 소스로 떨어지도록 만들었습니다 — kis:price 실시간 틱 → KIS REST 현재가 → price_history 최신 종가 → base_price. 어느 단계에서 왔는지를 가격 출처(실시간/종가)로 화면에 명시합니다.

멀티 워커에서 WebSocket이 중복 구독되지 않도록 Redis 리더 락 kis:ws:leader로 단일 스트림을 보장하고, 10초 TTL 캐시로 표시가와 체결가가 벌어지지 않게 고정합니다. 종가는 GitHub Actions가 평일 16:30 KST에 수집합니다.

03  GAMIFICATION

미션 · 포인트 · 기프티콘

거래·학습 이벤트가 발생하면 미션 엔진이 조건을 재평가하고, 달성분은 포인트 원장에 적립합니다. 포인트는 기프티콘으로 교환되고, 운영자는 신청을 취소·전액 환불할 수 있습니다. 재고는 -1 = 무제한, 0 = 품절 계약으로 분리했습니다.

보상 설계 자체를 한 번 갈아엎었습니다. 수익률 보상 미션은 은퇴시키고 최대낙폭 15% 이내 유지· 3종목 동시 보유 같은 위험관리 미션으로 대체했습니다.

04  RANKING

스케줄러 없는 월간 랭킹

랭킹을 ‘가입 후 누적’에서 월간으로 바꾸면 매달 1일 KST에 기준을 초기화해야 합니다. 초기화 배치를 두는 대신, 집계 시점에 이번 달 기준 NAV가 없는 사용자를 멱등하게 일괄 INSERT하도록 만들었습니다.

결과적으로 스케줄러가 없어도 월 전환이 자동이고, 캐시 키에 월을 넣어 지난달 캐시는 자연 무효화됩니다. 죽은 경로였던 종전 TWR 계산은 제거했습니다.

Debugging

근본 원인까지 내려간 결함

증상을 가리는 대신 원인 계층까지 내려가 고친 사례입니다. 재현되지 않는 테스트 환경이 결함을 숨기고 있던 경우가 가장 많았습니다.

증상

모든 미션이 한 이벤트씩 늦게 달성 처리됨

원인

운영 세션이 autoflush=False라 미션 평가 SELECT가 같은 트랜잭션의 pending 주문·포지션을 보지 못했다. 테스트 conftest는 autoflush 기본값이라 결함이 재현되지 않았다.

조치

_evaluate_codes 진입 시 flush. 회귀 테스트를 운영과 동일한 세션 설정으로 재작성해 테스트가 결함을 잡도록 만들었다.

증상

운영 배포 후 미션 화면이 통째로 비어 있음

원인

빈 DB 초기화 경로가 create_all + alembic stamp head였다. stamp는 스키마를 ‘적용됨’으로 표시만 하고, 마이그레이션 안의 데이터 시드는 실행하지 않는다.

조치

시드 상수를 로드해 멱등 반영하는 seed_data_sync를 release 커맨드에 넣었다. 스키마와 시드의 책임을 분리한 것이 핵심.

증상

웹 배포판에서 아이콘이 전부 ☒로 렌더됨

원인

wrangler pages deploy가 node_modules 경로 자산을 업로드에서 제외 → 아이콘 .ttf 요청이 SPA fallback(text/html)으로 200을 받아 FontFace 파싱이 거부됐다. 200 응답이라 네트워크 탭만 보면 정상으로 보였다.

조치

배포 스크립트가 assets/node_modules를 assets/vendor로 rename하고 번들 경로를 치환하도록 수정. 배포 후 font/ttf Content-Type을 실측 확인했다.

증상

종목 검색에서 한 글자 칠 때마다 포커스와 키보드를 잃음

원인

검색창이 FlatList의 ListHeaderComponent에 컴포넌트 함수로 들어가 있었다. 리렌더마다 새 타입으로 인식돼 헤더가 통째로 리마운트됐다.

조치

검색창을 리스트 밖 고정 영역으로 분리하고, 검색창 2개를 1개로 통합했다. 자동완성과 목록 필터를 한 입력이 담당한다.

증상

홈 총자산이 0원으로 고정되는 경우가 있음

원인

숫자 카운트업이 requestAnimationFrame 기반인데, 비활성 탭이나 백그라운드 앱에서는 rAF가 멈춘다. 애니메이션이 시작값 0에서 영구 정지했다.

조치

문서가 비활성이면 즉시 최종값을 적용하도록 변경. 중요한 정보가 애니메이션 완료 뒤에만 보이지 않게 하는 원칙을 컴포넌트에 못 박았다.

Product decisions

기능을 덜어낸 결정들

사용자가 미성년자라는 조건이 기능 추가보다 기능 제거를 더 많이 요구했습니다.

ETF를 지원하지 않는다

레버리지·인버스까지 딸려 들어오는 위험 노출을 청소년에게 열지 않기로 했습니다. 화면에서 감추는 데 그치지 않고 instruments 테이블의 관련 컬럼까지 마이그레이션으로 제거했습니다.

수익률을 보상하지 않는다

수익률 미션은 필연적으로 몰빵을 유도합니다. 시즌 최대낙폭 15% 이내 유지, 3종목 동시 보유처럼 위험을 관리했을 때 보상이 나오도록 바꿨습니다.

거래 시간은 fail-closed

환경변수가 비어 있으면 거래가 열리는 게 아니라 막히는 쪽이 기본값입니다. 운영 설정 실수가 곧 통제 없는 거래로 이어지지 않게 했습니다.

외부 연동은 전부 선택적

SMS·뉴스·환율·푸시·운영자 알림 키가 없으면 에러 대신 해당 기능만 조용히 비활성화됩니다. 부가 기능의 장애가 거래와 학습을 막지 않습니다.
